# 如何让个人档案持续成长，而不是成为一次性文档

## 为什么用GitHub
Markdown跨平台、Git保留版本、可用Codex批量编辑、能分文件分主题关联项目。GitHub保存的是**你提交的文件**，ChatGPT并不会因为本地多了一条聊天就自动更改GitHub；需要手动同步或在明确授权和连接后执行提交。

## 推荐更新节奏
- **事件触发**：发生重大选择/失败/原创灵感/实际收入/职位变化后，当天或一周内新增条目。
- **每周15分钟**：对照未完成行动，补交付证据、下一步、日期；不把日常琐事写成流水账。
- **每月30—60分钟**：回顾“哪些判断修正”“哪些项目已结案”“是否产出或获得真实客户”，更新职业、AI、财务风险和目标。
- **每季度**：整理重复、归档失效方案，核对身份信息与所有外部链接；可创建只含脱敏内容的公开总结。

## 一次更新的七步流程
1. 先识别记录类型：`FACT`事实、`IDEA`灵感、`DECISION`决策、`PROJECT`项目、`REVIEW`复盘。
2. 保存**发生日期和首次谈话日期**，保留来源，注明是否用户原话。
3. 选择对应文件，追加新条目；若推翻旧决策，不删除旧记录，标 `[S]` 和链接。
4. 对项目必须写：目标、投入、真实交付、证据、结果、失败或风险、下一步。
5. 如属重要事件，追加 `data/events.jsonl`，每行一个JSON。
6. 在 `CHANGELOG.md` 写一条变更说明，运行敏感信息辅助检查并人工复核。
7. Git commit并同步至**私有**仓库，必要时手工更新公开版。

## Windows用户首次上传（命令行）
登录GitHub，创建名为 `you-million-life-os-private` 的**Private空仓库**（不勾选初始化README，因本包已有）。解压至本地，确认在仓库根目录执行：

```powershell
git init
git branch -M main
git add .
python scripts/build_master.py
python scripts/check_sensitive.py
git status
git commit -m "docs: initialize personal knowledge archive 2026-11-23"
git remote add origin https://github.com/YOUR_USERNAME/you-million-life-os-private.git
git push -u origin main
```

`YOUR_USERNAME`必须改为自己的GitHub用户名，不能照抄。需已配置Git和GitHub身份验证。**脚本不扫描Git历史、附件和图片中的内容，不代表安全审核已完成。**

也可用GitHub Desktop导入本地文件夹并选择保密后发布；网页端的上传适合少量文件，初次包含多级目录推荐Git或Desktop。

## 后续更新（Windows PowerShell）
```powershell
# 在已克隆的私人仓库根目录
python scripts/new_entry.py idea "今天的一个灵感"
# 手动编辑生成文件并补充事实/来源
python scripts/build_master.py
python scripts/check_sensitive.py
git diff
git add .
git commit -m "docs: add idea and update progress"
git push
```

## 提交前务必判定
- 当前文件是由本人授权公开的吗？不是，则不要把私库推向公有。
- 第三方姓名/合同/电话号码是否泄露？
- 是否把未实现目标写成成绩？
- 是否保留了旧版，而不是静默篡改历史？

## 发布公开版
公开包是单独生成的人工脱敏资料库，不从私人仓库的历史提交中切换Visibility获得。可以创建 `you-million-life-os-public` **Public** 仓库。所有公开内容要从零重新审核，不要自动同步 private 内容。

## 备份建议
私人仓库至少保留一份本地备份；若未来需要保存真实合同和证件，只放独立加密存储，在Git存储“参考文件已在本地保险库”这种不泄密的索引。
