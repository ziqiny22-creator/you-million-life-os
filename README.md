# 尤百万人生档案 · You Million Life OS

> 档案版本 `v1.3.0`　｜　资料快照 2026-11-25（北京时间）　｜　当前目录为私人维护源

我是尤百万。这是我持续维护的一份个人档案。我希望将来换了模型、智能体或平台，只要对方能读取这些文件，就能了解我的经历、现阶段的重点和做事习惯，并用这些信息帮助我工作、学习和做决策。

## 1. 项目要解决什么

- **个人信息分散。** 我的经历、计划和复盘分布在不同对话、项目和本地文件里。换工具时，往往要从头解释一遍。
- **旧记录容易被当成现状。** 一件事可能从想法走到试做、交付，也可能被暂停。档案保留时间、来源和状态，让读者知道一条记录适用于哪个阶段。
- **了解之后还要能做事。** 我的职业、健身和项目都会继续变化。更新档案时，我会补进展和结果，让下一次分析可以沿着已有工作往前走。

## 2. 我希望用它做什么

**给能读文件的 AI 提供个人背景。** 让它先理解我重视什么、判断事情的方式和目前面临的限制，再给出具体建议或交付物。可以用来安排试讲、复盘工作、比较项目取舍，或整理一次重要决定。

**长期跟进我的人生状态。** 持续记录做过的事、调整过的方向、实际结果和还需确认的问题。项目使用 Markdown、JSON 和 JSONL，换工具时可以交给另一个模型阅读，也可以自行检查或修改。每次使用以当时提供的档案快照和我最新确认的信息为依据。

### 先认识我（截至 2026-11-25）

- **职业。** 我有给排水科学与工程的本科背景，后来进入公考培训行业。2026 年 8 月中旬第一次正式讲授综A。近阶段已听完国税面试基础课，正在模拟试讲。
- **健身。** 我从 2025 年开始系统健身。当前重点是保持全身体态，近一到三个月希望腿部肌肉更发达。职业和健身是我现阶段的两条主要发展方向。
- **做事习惯。** 我喜欢弄明白事情为什么如此，偏好直接、有条理、可核对的表达。做复杂任务时，希望先拆清问题、负责人、交付物和验收标准，再推进实际工作。
- **项目取舍。** 高校站长是现阶段准备发展的副业，仍在等总部统一培训。遇到重要取舍时，现阶段我更常用 yisun 决策系统。

## 3. 如何安装

这是一个文件型项目。**阅读档案只需获取文件**，用 Markdown 编辑器或能读文件的 AI 打开即可。

1. **已有本地目录或 ZIP**。打开现有目录，或将完整项目 ZIP 解压到一个文件夹。以同时包含 `README.md` 和 `MANIFEST.json` 的目录为项目根目录，保留原有子目录结构。
2. **从 GitHub 获取**。仓库发布后，可以下载并解压仓库 ZIP，或在已安装 Git 的环境中克隆。命令中的地址请替换为你有读取权限的实际仓库地址。

   ```powershell
   git clone "实际仓库克隆地址" "you-million-life-os"
   cd "you-million-life-os"
   ```

3. **交给 AI 读取**。支持文件夹或仓库读取的智能体可从根目录的 README 开始。只支持上传单个文件时，可以提供[单文件阅读版](个人完整档案_单文件阅读版.md)。

**运行维护脚本时**，需要 Python 3。在项目根目录运行 `python --version` 检查环境。Windows 上如使用 Python 启动器，也可用 `py -3 --version`，并把后续命令里的 `python` 换成 `py -3`。脚本使用标准库，确认版本后即可按[更新流程](#7-怎么继续更新)操作。

## 4. 信息怎么读

1. **第一次读**，先看[个人档案](01_个人画像/个人档案.md)、[性格与工作方式](01_个人画像/性格与工作方式.md)和[未来行动与风险清单](08_持续更新/未来行动与风险清单.md)。先了解我是谁、目前重视什么、哪些事正在推进。
2. **有具体任务**，按下表打开对应主题，需要时间顺序时再查[大事记](07_时间线/2026年大事记.md)。遇到不同口径，查看[本人确认记录](00_使用说明/待你确认的问题.md)、[本地补全来源](00_使用说明/本地补全来源.md)或[补充包合并核对](00_使用说明/补充包合并核对.md)。
3. **只能提供一个文件**，使用[单文件阅读版](个人完整档案_单文件阅读版.md)作为上下文。它汇总主要主题。需要追查来源、核对状态或修改记录时，回到主题原文件。
4. **需要批量读取**，从[结构化事实](data/facts.json)和[事件索引](data/events.jsonl)取相关条目，再回到主题文件补语境。事实在 `facts` 数组中，可按 `id` 或 `field` 查找，并查看 `as_of`、`evidence`。事件每行一条 JSON，分别记录 `event_date` 和 `logged_at`。档案版本和快照日期见 [MANIFEST.json](MANIFEST.json)。

## 6. 信息读取演示

**示例提问**

> 我这周想推进国税试讲，也想把健身保持住。高校站长先做到哪一步合适？请根据档案给我一个可执行的安排，并标出你用到的依据。

**读取顺序**

先看[个人档案](01_个人画像/个人档案.md)确定职业和健身的优先级，再查[职业成长历程](02_职业与教学/职业成长历程.md)、[健身与生活目标](06_生活与决策/健身与生活目标.md)和[创业项目总档](05_项目与商业/创业项目总档.md)核对三项的阶段。使用结构化索引时，可先查 `goal-002`、`career-005`、`career-008`、`fitness-002`、`project-005`。

**按这份快照可以回答**

- **档案依据。** 截至 11 月 25 日，国税已听完基础课，现处于模拟试讲阶段，计划逐步归档实际片段。健身以保持全身体态为主，近期目标侧重腿部。高校站长还在等待总部培训，已有选校筹备记录。
- **本周建议。** 优先录一段国税模拟试讲，回看时记下一处问题和下一次的改法。沿用自己的健身节奏，留下当周训练记录。高校站长先整理说明会需要确认的规则，把培训后的行动安排留到获得准确信息之后。
- **还要确认。** 排到具体日期前，请本人确认本周可用时间和正式考核日期。

## 7. 怎么继续更新

1. 有新进展时，补到对应主题。记下发生时间、确认时间、来源，以及进展目前处于计划、尝试、交付还是已经有结果的阶段。
2. 重要变化同步到[事实索引](data/facts.json)、[事件索引](data/events.jsonl)和[变更日志](CHANGELOG.md)。更新状态时保留能解释变化的必要历史。
3. 需要新建独立笔记时，任选灵感、决策、项目或复盘模板。更新完主题后，可重建单文件阅读版，再检查相对链接和可见范围。

在项目根目录用 Python 3 运行以下命令：

```powershell
# 可选，创建一篇本地灵感草稿
python scripts/new_entry.py idea "一次试讲后的灵感"

# 填完并核对主题文件后，重建阅读版并检查文本
python scripts/build_master.py
python scripts/check_sensitive.py
```

| 脚本 | 实际作用 |
| --- | --- |
| [new_entry.py](scripts/new_entry.py) | 根据 `idea`、`decision`、`project`、`review` 模板创建本地 Markdown 草稿，正文和索引由维护者填写。 |
| [build_master.py](scripts/build_master.py) | 按顺序拼接主题 Markdown，覆盖生成版。主题文件是编辑入口。重建后复核生成版的内嵌相对链接，查阅资料也可使用 README 的导航。 |
| [check_sensitive.py](scripts/check_sensitive.py) | 在支持的文本格式中按规则定位部分疑似敏感信息。是否适合对外提供由人工复核。 |

脚本使用 Python 标准库。状态变化由本人补充和确认，维护者审核后提交需要共享的快照。详细步骤见[维护手册](08_持续更新/维护手册.md)。
